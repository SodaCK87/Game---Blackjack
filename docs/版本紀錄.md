## v0.12.1（2026-10-28）大特效第一次播不再頓一下、特效期間不重畫牌桌；npm test 快一倍

處理 2026-10-27 那輪盤點的效能熱點 P-14、P-13、P-06、P-11、P-09、P-10，以及 `npm test` 平行跑時隨機紅一條（併 A-03）。玩法沒有改。改前改後的數字見 `docs\perf-baseline.md` 第 3 輪。

1. 大特效開頁後第一次播會頓 1～3 格（每格 55–310 ms）：時間花在第一次作畫，不是 script。開頁後閒下來時，`showcase.js` 的 `rehearse()` 用透明度 0.4% 的外框（`.bigfx-warm`，不叫 `bigfx`，探針與量測不會把它算成一段特效）把你拿 Blackjack 與加倍各快播 0.3 秒，籌碼圖也在這時先轉好。預演照真實時間播，不跟 `anim.speed`，也不算進 `anim.busy`。開頁後第一段你拿 Blackjack 與加倍，桌機、手機各 5 次共 20 次：改前 20 次每次 2–3 格，改後 19 次 0 格、1 次 2 格（判成背景負載）。
2. `anim.js` 的 `wait()` 不再每一格都重畫 3D 牌桌，只在開始時補畫一次。對白、橫幅、大特效等待的那幾秒原本一直在重畫：大特效每段 236–355 次（被暗幕蓋住），一局裡每段 0.5–2.1 秒。現在大特效每段 1 次，一局裡每段 13–35 ms。量測腳本會換掉 `anim.tween`，所以 `wait()` 改成直接走內部的 `run()`。
3. `game.js` 的 `state()` 不再走 JSON 來回，改成逐層拷貝（牌、手、結算結果都是新的物件）。規則引擎一萬局從 2,292 ms 降到 372 ms，`mutants` 從 82 秒降到 60 秒。
4. 測試：
   1. `check_ui.js` 切成三支加一支共用的 `ui_util.js`（`check_ui_rounds.js` 打局的按鈕流程、`check_ui_text.js` 畫面上的字），讓 node 平行跑。43 個 `test()` 呼叫處全部搬過去，條數不變。
   2. `browser_util.js` 收尾改寫（P-10、A-03）：
      1. 先問瀏覽器自己開了哪些進程，關掉後用 pid 等它們結束，最多等 10 秒。機器忙時子進程收得慢，原本會數到正在結束的進程而假紅。
      2. 再用常駐的 PowerShell 照 user-data-dir 查一次 CIM，每次約 0.18 秒（原本每一頁起一支 PowerShell 要 0.8 秒）。瀏覽器自己報的清單漏掉 crashpad-handler，所以這一步不能省。陽性對照：塞一支帶同一個標記、不會自己結束的 Edge，等 10 秒後被收掉，node 照常結束。
      3. 開頁逾時從 15 秒放寬到 60 秒（全套平行跑時 `Page.navigate` 逾時過一次）。
      4. 啟動加 `--disable-extensions`、`--disable-sync`。
      5. 開頁後斷言 `visibilityState` 是 `visible`，不是就報「量法錯」。
      6. 刪不掉的設定檔重試 5 次，下一次載入時再補刪一小時以前的。
   3. 平行跑時隨機紅的另外兩條：
      1. `check_play.js` 的三個大特效陽性對照，卡住門檻放寬到 2 分鐘：破壞過的特效照真實時間等，8 局會超過原本的 40 秒。
      2. `fx_util.js` 判斷「播的時候牌局往下演」改比牌與籌碼的世界座標，不只比數量：機器忙時一格就超過 40 倍速的特效長度，籌碼還在飛、還沒收走，只比數量看不出來。
   4. 新增 5 條：`check_fx.js` 4 條（有預演、看不到、牌桌不震、播完收掉，對照是拿掉觸發與拿掉透明；大特效 2 秒裡最多補畫 2 次，對照是改回每一格都重畫，325 格重畫 324 次），`check_game.js` 1 條（改 `state()` 的回傳值碰不到牌局，`mutants` 加一列）。
   5. 全套 203 條；`tools/measure_perf.js` 的 `npm test` 段連跑 6 次（含 warmup）全綠，中位數 276 秒（原本 459 秒）；`npm run mutants` 61 個全部抓到。

## v0.12.0（2026-10-23）三段大特效：你拿 Blackjack、荷官翻出 Blackjack、你加倍

研究 session 做的原型，使用者 2026-10-23 看過定案，交給主線接進遊戲。新檔 `app\js\view\showcase.js` 掛在 `V.fx`，`index.html` 排在 `effects.js` 之後、`director.js` 之前；`director.js` 在原本的 handler 裡 await，沒有新增事件種類。時間一律除以 `anim.speed`（`speed = Infinity` 直接完成），播完把元素、body 上的震動 class 與時間變數收乾淨，全屏層 `pointer-events: none`。

1. 你拿 Blackjack（`blackjack`，你的座位）：2.0 秒，取代 1.4 秒的 BLACKJACK 橫幅。閃白、金色放射光芒、荷官驚訝臉的圓框大特寫彈出、兩波共 40 片籌碼從大頭後面噴出、「BLACKJACK!」砸下來牌桌震一下、「賠 1.5 倍！」、淡出。分 A 兩手都中時同一局只播第一次，第二手只講對白（BJK-05 的用意不變）。
2. 荷官翻出 Blackjack（`dealerBlackjack`）：2.0 秒，紅色光芒、荷官得意的笑臉、「BLACKJACK」「莊家通殺！」，取代原本講完對白後等的 1 秒。
3. 你加倍（`double`，你的座位）：2.4 秒，播完才把加倍那疊籌碼推上桌。左上角荷官挑眉「加倍？！」，右下角你的手蓄力後把這一注最大面額的籌碼彈上桌，鏡頭推近 2.3 倍，籌碼斜躺著嗡嗡搖晃、停下時面額朝正，「加倍！」「押兩倍・只再發一張」。
4. 實測 handler 長度（正常速度、無頭 Edge、每次新開頁各三局）：你拿 Blackjack 2,078–2,084 ms（v0.11.1 的橫幅 1,416–1,548）、荷官 Blackjack 2,074–2,084 ms（原本 1,015–1,024）、加倍 2,884–2,886 ms（含推籌碼 0.42 秒，原本 425–430）。開頁後第一次播多約 70 ms 的準備（籌碼貼圖轉成圖檔、第一次排版），同一頁之後的特效 2,012–2,024 ms、加倍特效本身 2,413–2,417 ms。沒有特效的一般一局（疊好的牌，兩版交替各五局）整局中位數 10,774 ms 對 10,770 ms，發牌之後的部分 6,593 對 6,589 ms，沒有變長。
5. 跟原型不一樣的地方：
   1. 大標往下挪 0.2 個字高（副標不動），最後推近改成以嘴的高度往上長（BJK-04 的用意）：大標斜 3 度、右半邊比較高，照原型的位置，大標上緣會壓進荷官笑臉五官的範圍約 13 px（由現在的量測推算），最後推近時整張臉還會長到大標底下。現在大標離五官最近：桌機 16.8 px、直式手機 15.6 px、橫式手機 8.6 px。
   2. 大頭框原型偏右 8 px（`margin-left` 只扣了內容寬的一半，沒扣邊框），改成正中。
   3. 尺寸多夾一個 vh：橫拿的手機 844×390 照原型的大小，副標會掉出畫面底下。桌機 1280×720 與直式 390×844 算出來跟原型一樣。
   4. 噴出的籌碼翻面時面額字左右相反：`scaleX` 改用絕對值（籌碼兩面都印面額，翻到背面字照樣是正的），壓扁成一條線的那一刻補一格關鍵影格。

   6. 每片籌碼晚出發的那一點從壽命扣掉：原型最後幾片最多比特效晚 4% 才播完。噴籌碼的亂數改用 `V.rng`（跟金幣雨一樣），不碰牌局的亂數。

   2. `check_ui.js` 的 BJK-04 改量大特效：大標落定到播完每 3% 暫停一次，大標與副標看得到的字不碰大特寫的五官（`g.face`）與畫面上荷官的臉（`faceRect()`），也不跑出畫面，桌機、直式、橫式手機都量；陽性對照：大標放回大特寫正中央 → 手機上兩張臉都壓到。BJK-05 改數大特效出現幾次＝1；陽性對照：拿掉只播一次 → 2。

## v0.8.0（2026-10-22）拉斯維加斯大廳背景

使用者選了「拉斯維加斯大廳」並要求整體調暗、避免太花，背景是靜態的。原本牌桌後面只有一片深藍灰，直式手機上方約三分之一是空的。

1. 新的 `view\room.js`：荷官背後 5 單位一道木牆板隔間，上緣有黃銅扶手；牆後是大廳的暗處，放著吃角子老虎與水晶燈的失焦光點；地板換成地毯花紋。貼圖都在 `textures.js` 裡用 canvas 現畫，不用外部圖檔。
2. 光點照「畫面位置」排，不照世界座標排：每次版面重排時，從鏡頭沿視線放到牆後 3–15 單位，大小換算成固定的 CSS 像素。這樣做的原因是鏡頭會依螢幕比例換角度，照世界座標擺的話，桌機的仰角只看得到一小條，手機又看到另一段。吃角子老虎分成六排，越上面越遠，光點越小、越密，看起來有景深。
3. 地板的遠端停在牆腳，所以牆後面沒有地板，只有大廳的暗處與光點。
4. 新的 `check_room.js`：桌機、直式手機、橫式手機、平板、超寬螢幕五種比例都斷言三件事。
   1. 牆上緣以上至少留一成畫面。實測桌機、橫式手機、超寬螢幕都是 18%，平板 40%，直式手機 57%。
   2. 光點都在牆後面。
   3. 只畫佈景時，大廳與牆加地毯的平均亮度都不到絨布的四成。實測約兩到三成。
5. 三個陽性對照都確實變紅：光點擺到牆前、大廳底色調亮、牆加高到擋住大廳。
6. `V.stage` 多開放 `camera`、`renderer`、`room`，給探針讀畫素用。README 的截圖換成新背景。

## v0.7.2（2026-10-22）阿德的 A+A 對 6 改成加倍

v0.7.1 對照時只有這一格不一致：表寫要牌，「建議」是加倍。公開的表在這格是分牌，這個遊戲不能分牌，表原本退回要牌。使用者同意改表。

1. 改之前先確認哪邊對，因為勝率提示是近似算法，差距又小。另寫一支逐張扣牌的精確計算（6 副牌扣掉 A、A、明牌，荷官軟 17 停，要牌之後每一步都選最有利的），只用來做這個決定，沒收進 repo。

   | A+A 對 | 要牌 | 加倍 | 結果 |
   | --- | --- | --- | --- |
   | 2 | 0.0838 | −0.0630 | 要牌 |
   | 3 | 0.1060 | 0.0030 | 要牌 |
   | 4 | 0.1290 | 0.0712 | 要牌 |
   | 5 | 0.1607 | 0.1408 | 要牌 |
   | 6 | 0.1880 | 0.1907 | 加倍，多 0.27% |
   | 7 | 0.1643 | −0.1764 | 要牌 |

   數字是每押一單位的平均輸贏。勝率提示的近似算出對 6 加倍多 0.20%，方向相同。
2. `strategy.basic`：軟 12（只會是 A+A）對 6、可以加倍時加倍，其餘照舊要牌。牌局裡的阿德也照這張表打，該加倍時仍有 10% 不敢加倍。
