# 檔案結構規範

**職責**：這個 repo 的檔案放哪、怎麼命名、文件寫多長、缺陷怎麼編號。
**型別**：從頭讀型　**份量上限**：150 行（超過就把長篇說明下放到 `docs\檔案結構規範-附錄.md`，原處只留一行連結）

規則一眼判定合不合規，沒有「盡量」「建議」這種寫法。跨專案通則在全域 `~\.claude\CLAUDE.md`，這裡不重複。

## 頂層資料夾

每個只放一種東西，列舉得完，沒有「其他」。根目錄只准放 `README.md`、`目標路線圖.md`、`CLAUDE.md`、`.gitignore`、`.gitattributes`。

| 資料夾 | 只放 | 何時建 | 進版控 |
| --- | --- | --- | --- |
| `app\` | 玩遊戲時瀏覽器會載入的檔案；也是 GitHub Pages 的發布根目錄 | 預設建，放 `.gitkeep` | 是 |
| `tests\` | 由 node 執行、目的是驗證 `app\` 的腳本，與它們讀的素材 `tests\fixtures\` | 預設建，放 `.gitkeep` | 是 |
| `docs\` | 版本紀錄、問題台帳、本檔，與 README 用圖 `docs\img\` | 預設建 | 是 |
| `tools\` | 由 node 或 python 執行、不是在驗證東西的腳本（單檔打包、產貼圖） | 有才建 | 是 |
| `dist\` | 打包給同事離線雙擊的單一 HTML | 有才建 | **否**，跑 `tools\` 的打包腳本隨時重建 |
| `.github\` | GitHub 讀的設定（Pages 部署 workflow） | 有才建，階段 6 | 是 |

### `app\` 照測試成本分兩邊

`core` 用 node 直接跑、毫秒級、結果可重現；`view` 要開瀏覽器才測得到，成本高一個量級。能放 `core` 的邏輯一律放 `core`。

| 位置 | 只放 | 何時建 |
| --- | --- | --- |
| `app\` 根 | `index.html`、`style.css` 兩個檔 | 階段 0 |
| `app\js\core\` | 規則、牌靴、點數、結算、AI 決策、版號 `version.js`。規則見 [CLAUDE.md](../CLAUDE.md) 第 3 條 | 階段 1 |
| `app\js\view\` | 3D 牌桌、插畫荷官、動畫、按鈕與介面。可以 import `core`，反方向不行 | 階段 2 |
| `app\lib\` | 第三方函式庫原檔（Three.js），內容不改 | 階段 0 |
| `app\img\` | 荷官 SVG 與其他遊戲用圖 | 階段 3 |

## 新檔案放哪：照這串問句走

由上往下問，第一個答「是」的就是答案。

```
1. 同事要知道去哪玩、怎麼玩嗎              → README.md
2. 這一版動了什麼嗎                        → docs\版本紀錄.md（只寫編號，不重述內容）
3. 有東西壞了／曾經壞過嗎                  → docs\問題台帳.md，配一個 BJK-NN
4. 還沒做、要不要做嗎                      → 目標路線圖.md
5. 每次執行都會重新產生、刪掉也無妨嗎      → 打包檔進 dist\；其餘進產生它的腳本旁邊、
                                              `_` 開頭的資料夾（例：tests\_out\）
6. 玩遊戲時瀏覽器會載入它嗎                → 是就往下問 6a–6e，否就跳 7
   6a. 第三方寫的嗎                        → app\lib\
   6b. 圖檔嗎                              → app\img\
   6c. 是 index.html 或 style.css 嗎        → app\ 根
   6d. 碰 DOM／Three.js／計時器嗎           → app\js\view\
   6e. 以上皆非                            → app\js\core\
7. 由 node 執行、目的是驗證別的東西嗎      → tests\
8. 驗證腳本要讀的素材嗎                    → tests\fixtures\
9. 由 node 或 python 執行的其他腳本嗎      → tools\
10. GitHub 要讀的設定嗎                    → .github\
11. README 要用的圖嗎                      → docs\img\
以上皆非                                   → 停下來問使用者，不准自己開新資料夾
```

⚠️ 第 5 問排在第 6 問前面：探針截圖也是瀏覽器產的，先問「刪掉也無妨嗎」才不會被導進 `app\img\`。

## 命名

| 對象 | 規則 |
| --- | --- |
| 資料夾、程式檔 | 英文小寫，底線分隔（`shoe.js`、`check_engine.js`） |
| 驗證腳本 | `tests\check_<對象>.js`，一支守一個對象 |
| 文件 | 中文（`版本紀錄.md`） |
| 暫存資料夾 | `_` 開頭；來源資料夾不准用 `_` 開頭，否則會被 `.gitignore` 的 `**/_*/` 擋掉 |
| 日期 | `YYYY-MM-DD`，不用其他格式 |
| 版本 | **現行版檔名一律不帶版號**。自己的程式：唯一來源是 `app\js\core\version.js` 的 `BJK_VER`，發布時打的 git tag `vX.Y.Z` 必須與它相同。第三方函式庫：以檔內常數為準（Three.js 是 `REVISION`） |

## 不進版控的東西

| 類別 | `.gitignore` 那一行 | 能不能重建 |
| --- | --- | --- |
| 暫存資料夾（探針輸出、截圖） | `**/_*/` | 能，重跑產生它的腳本 |
| 單檔打包產出 | `dist/` | 能，跑 `tools\` 的打包腳本 |
| node 套件 | `node_modules/` | 能，重新安裝 |
| Windows 縮圖與資料夾設定 | `Thumbs.db`、`desktop.ini` | 不需要 |

## 文件

| 文件 | 只放 | 型 | 上限 |
| --- | --- | --- | --- |
| `README.md` | 給同事看：去哪玩、怎麼玩、已知限制、驗到什麼程度。只寫玩家看得懂的話 | 從頭讀型 | 400 行 |
| `目標路線圖.md` | 里程碑、現在卡在哪、**明確不做的事** | 從頭讀型 | 120 行 |
| `docs\版本紀錄.md` | 每一版改了什麼、為什麼那樣改 | 敘事追加型 | 12 個版本，超過切 `docs\版本紀錄_歷史.md` |
| `docs\問題台帳.md` | 每個缺陷一列 | 查詢型 | **不設上限、不切檔**，靠「狀態」欄過濾 |
| `docs\檔案結構規範.md` | 本檔 | 從頭讀型 | 150 行 |
| `CLAUDE.md` | 只在這個 repo 成立的規則 | 從頭讀型 | 40 行 |

量行數用 `wc -l` 或 `(Get-Content $p -Encoding UTF8).Count`，兩者交叉對一次。

## 缺陷編號、嚴重度與狀態

編號 `BJK-NN`（兩位流水號，從 01 起），**一經配發永不重用**。其他文件提到它時只寫編號、不重述內容。

| 嚴重度 | 判準 |
| --- | --- |
| 高 | 玩不下去（卡住、當掉），或籌碼算錯 |
| 中 | 畫面或動畫錯，但不影響結算 |
| 低 | 外觀、文字 |

| 狀態 | 意思 | 進場條件 |
| --- | --- | --- |
| 🔴 開放 | 確認是缺陷，還沒修 | 有可重現的證據（現況輸出 vs 應有輸出） |
| 🟡 待驗 | 改好了，還沒有測試守著它 | 程式已改 |
| ✅ 已修 | 有斷言或探針守著，重跑會紅 | **做過陽性對照**：把修正拿掉，那條真的變紅 |
| ⏸ 不修 | 確認存在但決定不動 | 寫清楚為什麼（實測非瓶頸／代價不成比例） |

還不確定是不是缺陷的事（風險、待驗證的假設）不進台帳，進 `目標路線圖.md`；驗出來真的壞了才配編號。
