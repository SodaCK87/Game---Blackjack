# 把 GPT 插畫換進牌桌

| 你要做的 | 去哪一節 | 速答 |
| --- | --- | --- |
| 挑這輪要換什麼 | 先對方向 | 從 `textures.js` 找還在用 canvas 現畫的函式，給 2–3 組讓他選 |
| 寫給 GPT 的提示詞 | 提示詞一次給一整段 | 整段貼一次，讓它依序連續生；平光、沒有透視、鋪滿四邊、不要字；提示詞下方直接寫存檔的完整路徑與檔名 |
| 圖放進來了要接上 | 原圖進 fixtures、產生器寫進 `*_art.js` | PNG 轉無損 WebP，產生器縮圖寫進產出檔，帶雜湊判過期 |
| 改 `textures.js` | 載入：先畫純色版，解碼完補畫 | 補畫重傳前先 `dispose()`，不然 mipmap 會殘留舊圖 |
| 驗證與交付 | 測試、截圖、記錄 | 過期檢查、補畫判準、各自的陽性對照，截圖給他看，量 KB 與記憶體 |

標記體例：✅ 實測過／⚠️ 已知限制／📌 未查證。沒掛標記的是一般說明，不涉及事實宣稱。

## 先對方向

1. 我叫不動 GPT。分工是我寫提示詞與規格、使用者生圖丟進來、我寫產生器接上。
2. 候選清單從 `app\js\view\textures.js` 的 `V.textures` 列出來：還在用 `canvas()` 現畫、而且畫面上佔面積的才值得換。已經換掉的看 `tests\fixtures\*_art\`。
3. 純換貼圖的（材質、牌面）跟會加功能的（例如替 AI 同桌加頭像、要改版面）分開問，後者代價大很多。
4. 角色類（荷官、人物）的新圖，即使他說「替換」「換掉」，也要先問清楚：是取代舊的，還是多一款可以切換、哪一款當預設。舊角色被整套蓋掉，他到上線後才會發現。

## 提示詞一次給一整段

1. 使用者不想一張一張輸入。給一整段讓他貼一次：開頭寫「請依序生成 N 張獨立圖片，每張各自輸出，不要拼圖，中間不用等我確認，連續完成，訊息裡寫上檔名，不要畫進圖裡」，接著是共同要求，再來是編號的各張需求。
2. 共同要求固定寫這幾項：正面或正上方平視、沒有透視、鋪滿到四邊、光線均勻、沒有陰影反光暗角、不要邊框文字浮水印。明暗、縫線、高光、字由程式疊上去，GPT 的圖自己帶了光就會疊兩層。
3. ⚠️ GPT 只出 1:1、3:2、2:3 三種比例。貼圖比例對不上時，改請它畫「一個單位」再由產生器並排（牆板一段是兩塊鑲板，只請它畫一塊）；板面類的（素面加邊框與中央小圖案），就請它把圖案集中在中間，產生器再拿掉素面那幾列湊比例（發牌盒，v0.28.0）。要當形狀用的（紋章），請它畫黑底白線，金色由程式上。
4. 每張寫明檔名與比例。提示詞那一段的正下方，直接寫出存檔的完整路徑，例如 `C:\…\Game---Blackjack\tests\fixtures\scene_art\`，並列出每個檔名，讓他下載後照著存，不必再回頭問放哪裡。也要告訴他：不滿意的只要重生那一張就好。
5. 要平鋪的貼圖寫「可以無縫拼接」只會讓它盡量接近，真正接得起來是產生器的事。

## 原圖進 fixtures、產生器寫進 `*_art.js`

1. 原圖放 `tests\fixtures\` 底下：荷官每一款一個資料夾（西裝 `dealer_art\`、旗袍 `dealer_art_qipao\`，新一款就再開一個），牌面、牌背、籌碼、大廳、場景材質、道具在 `card_art\`、`chip_art\`、`room_art\`、`scene_art\`、`prop_art\`。測試拿它算雜湊判過期，所以放 fixtures、不放 `app\img\`。
2. 使用者給的 PNG 轉成無損 WebP，解回來逐像素比對相同，然後刪掉 PNG。⚠️ GPT 下載的檔名常是 `exec-<亂碼>.png`，沒照提示詞改：先逐張看圖認出是哪一張再改名，不要照檔案順序猜。
3. 產生器：荷官用 `tools\make_dealer_art.js` 寫 `dealer_art.js`；其餘共用 `tools\make_table_art.js`（新類別加進 `DIRS`）寫 `table_art.js`。不要另開一支，也不准手改產出檔。
4. ✅ 外部圖檔在 file:// 下上傳 WebGL 會被擋，所以一律縮圖轉成 data: URL 寫進 `.js`。WebP 品質 0.85。
5. 解析度由畫面上實際佔的裝置像素推（直式手機 390 寬、畫布密度上限 2），不比那個大；寫明依據，並記下產出檔增加的 KB 與解碼後記憶體（寬×高×4）。
6. 構圖中心、五官框這類手量的值，產生器要留對照圖在 `tools\_shots\*-marks.png`，換圖就重量、逐張看。
7. 要平鋪的貼圖由產生器量接縫落差，不夠就做交疊處理；並排、拉伸的比例寫進版本紀錄。接縫合不合格以 `tests\check_textures.js` 的 `seamProblems` 為準（接回來那一對像素差不超過圖裡相鄰像素差的 P99），產生器印的數字只是參考。
8. 插畫自帶的顏色亮度跟原本 canvas 版不同，用 `textures.js` 的倍數壓到原本那一級，量到的亮度寫進版本紀錄；要維持識別色的（例如絨布）只取插畫的明暗、不取顏色。

## 載入：先畫純色版，解碼完補畫

1. 開頁先畫原本的 canvas 版，插畫解碼完再補畫、重傳；`dealer.js` 的 `ready` 要等這些都好了才重畫那一次。不開動畫迴圈（CLAUDE.md 第 11 條）。
2. ✅ 補畫後原地重傳的貼圖，縮小用的 mipmap 層會留著舊的純色版，遠處的東西就髒了。重傳前先 `dispose()`。
3. WebP 解不開時維持 canvas 版，主控台留一行警告，牌照樣能玩。

## 測試、截圖、記錄

1. `check_table_art.js`／`check_dealer_art.js`（CI 也跑）：產出檔與原圖、產生器同步。陽性對照是換一張原圖、改品質，這兩種都要判過期。
2. `check_textures.js`：開頁補畫後貼的是插畫，跟純 canvas 版讀回來的不一樣。陽性對照是不補畫、原地重傳不 dispose，兩種都要判紅。⚠️ 探針要讓 `decode()` 晚幾百毫秒才回，否則解碼太快，補畫那條路根本沒走到。
3. 只跑相關的測試檔，再加 `check_power.js`（draw call 不能變多）。全套留到 push 前。
4. `node tools/shoot.js <前綴>` 截圖給使用者看；牌面、籌碼加 `--cards`，荷官加 `--dealer`。顏色、亮度、拉伸、鏡像這類我自己挑的取捨，要點名請他看。
5. `node tools/measure_frame.js <改前複本>` 比一格毫秒與開頁時間（複本用 `git archive HEAD app | tar -x -C <暫存>`）。
6. `version.js` 升版，`docs\版本紀錄.md` 寫一段：量到的亮度、KB、記憶體、手挑的取捨與「只在這台 Edge 看過」。
